## Why

The Architecture Coverage PR comment currently reports only aggregate coverage totals when
strict validation fails. Reviewers cannot identify the failed contracts or the evidence that
caused the gate to fail without downloading and inspecting the JSON artifact.

## What Changes

- Render a deterministic, reviewer-oriented list of failed architecture rules before aggregate
  coverage tables.
- Group diagnostics by contract and show the stable contract ID, name, concise evidence, and
  bounded representative diagnostics with an omitted-count indicator.
- Add unique failed-rule and failed-diagnostic counts to the summary table.
- Preserve concise passing reports and existing CI pass/fail behavior.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `architecture-coverage-ci-reporting`: failed PR comments explain each failed rule as well as
  reporting aggregate coverage counts.

## Impact

- `tools/scripts/architecture_coverage_report.py` and its script-level tests.
- The sticky Architecture Coverage PR comment generated by `.github/workflows/ci.yml`.
- No policy schema, linter strict/audit semantics, or GitHub Actions permission changes.
